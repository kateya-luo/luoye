固件联网后应通过 `/api/v2/build-info` 检查服务器版本、协议版本和能力列表。协议版本不一致时，不应假定上传、字幕或日程同步能够兼容。

## 固件 2.3.2 摘要

- 待机时钟与电池局部刷新，半小时执行一次整屏刷新。
- 录音界面采用单行实时字幕滚动；滚动纪要随每分钟 FAST 刷新显示最新内容。
- SD 卡 SPI 使用 20 MHz，上传采用稳定的单任务状态机；TCP 收发窗口为 32 KiB，HTTP TX 为 8 KiB。
- 存储升级到 `luoye-storage/2`：旧卡不会自动格式化，只能由用户长按录音键确认后初始化为 FAT32，并执行边界读写自检。
- SD 文件定位读取统一使用 POSIX `fstat/lseek/read`，修复非对齐边界读取失败。
- 活动会话、上传游标和 WAV 顺序读取句柄常驻内存，复用 authenticated HTTP keep-alive；上传进度每 8 片或 8 秒落盘一次。
- 保留 10 MiB 断点范围、单任务调度、DMA 安全清理、上传诊断和会话恢复能力。
- 新增 `LY|LIVE_UPLOAD_DIAG` 与 `LY|LIVE_CHECKPOINT`；60 分钟真机验收目标为长期 `lag_ms <= 3000`。

## 服务器 1.0.1 摘要

- 区分 partial/final 字幕事件，同一 `seg_id` 采用更新语义。
- 字幕、说话人和纪要使用独立变化通道，避免非字幕事件触发字幕重复。
- 离线转录按 5 分钟切片组织，可配置 4 个离线 worker；任务按上传开始时间排队。
- 保持 `luoye-device-api/2`、10 MiB 范围上传和设备会话恢复。

## 发布验证

1. 检查 `GET /api/v2/build-info` 返回 `server_version=1.0.1` 和 `api_contract=luoye-device-api/2`。
2. 验证录音、实时字幕、停止录音、离线上传、断点恢复和转录完成。
3. 验证待办同步不受录音上传清理流程影响。
4. 验证断网、重连、服务器不可达和设备复位后的恢复路径。
5. 验证旧卡只提示初始化、不自动格式化；确认初始化后完成 `luoye-storage/2` 自检。
6. 连续录音 60 分钟，检查实时上传延迟、检查点恢复以及 SD/DMA/看门狗日志。

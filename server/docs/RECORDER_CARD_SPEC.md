# 录音卡产品形态与交互规范（提纲挈领版）

> 目的：把产品形态、三键语义、模式切换、屏幕/LED/离线/电源的**全部决策**固化在此，
> 任何人（或任何模型）拿这一份 + `PLATFORM_ROADMAP.md` 即可继续开发，不依赖对话历史。
> 状态：v1 定稿待评审。硬件以 board.pdf / mic.pdf（2026-06-27 版）为准。
> **可点原型**：`apps/card-sim/index.html`（250×122 真机像素版：屏幕内部锁定真实分辨率再等比放大，带溢出检测；三键短按/长按/按住说话、提醒/断网/充电/SD满/锁键/开关机全可体验）。

## 0. 一句话定位

**放在桌上的"采集入口"卡片**：一键把会议/课堂变成纪要，把外语变成中文，把随口一句话变成日历里的待办。
重 AI 全在云端（ClearMeeting 服务器），卡片只负责：**可靠采集 + 常驻显示 + 三键捕获**。

硬件形态（卡片学习机）：2.13" 墨水屏在正面，右侧竖排三颗橙色圆键（上 REC / 中 MARK / 下 BACK），
顶部双硅麦开孔，USB-C 充电。ESP32-S3 + microSD + RTC + 电量计 + 三 LED（REC/FULL/CHG）。

## 1. 交互设计原则（五条，冲突时按序取舍）

1. **录音永远最高优先**：任何交互都不得中断采集；SD 先落盘、上传只是搬运；低电先写完 SD 再关机。
2. **一键到达核心动作**：REC 键永远=开始/结束当前场景的采集，无菜单、无二级确认（结束用长按防误触）。
3. **待办无处不在，不是模式**：任何状态下"按住 MARK 说话、松开即记"。两秒完成，绝不让用户"先切到待办模式"。
4. **盲操作可用**：三键语义在所有状态下保持同构（REC=采集，MARK=捕获，BACK=导航/退出），配合 LED 可不看屏操作。
5. **墨水屏只显慢信息**：15 秒节拍整段刷新（已实测定稿）；不逐字冒、不滚动动画；没新内容不刷。

## 2. 概念模型：两个采集场景 + 一个常驻层

```
┌─ 常驻层（永远在）────────────────────────────────┐
│  待机主屏 = 时钟 + 今日议程 + 下一个提醒            │
│  按住 MARK 说话 = 语音待办（任何状态下可用）         │
│  RTC 到点 = 提醒弹屏 + LED                        │
└──────────────────────────────────────────────────┘
        │ 待机页短按 MARK 轮换场景，REC 开始
        ▼
┌─ 采集场景（二选一，可扩展）───────────────────────┐
│  ① 会议/课堂：实时转写上屏，MARK 标重点，           │
│     结束后云端出纪要/课堂笔记                       │
│  ② 翻译/听译：逐句译文大字上屏（原文小字），         │
│     MARK 收藏句子；结束后出双语记录                 │
└──────────────────────────────────────────────────┘
```

- 「会议」与「课堂」是**同一场景的两个皮肤**（工作版/学生版在 App 里配置产品线，卡上只显对应措辞）。
- 「翻译」与「听译」同理是一个场景；翻译方向（中↔英等）在 App 配置，卡上不做语言菜单。
- **待办没有"模式"**：它=待机主屏的议程显示 + 全局按住-说话手势 + 到点提醒。这是本设计最重要的取舍。

## 3. 三键完整语义表

| 状态 | REC 短按 | REC 长按(1.5s) | MARK 短按 | MARK 按住说话 | BACK 短按 | BACK 长按(3s) |
|---|---|---|---|---|---|---|
| **待机主屏** | 开始当前场景采集 | （关机=长按5s，弹确认） | 轮换场景（会议⇄翻译） | **语音待办** | 翻页：议程⇄设备状态 | 进入配网/配对页 |
| **录制中** | 暂停/继续 | **结束会话** | 标记重点（计数+1） | 语音待办（同时记一个重点） | 切页：转写⇄状态（翻译场景：译文⇄双语⇄状态） | 锁键 |
| **提醒弹屏** | **一键开录**（自动以事件名命名会话） | — | 稍后提醒（+10分钟） | — | 知道了（关闭弹屏） | — |
| **锁键中** | 屏显"已锁定" | 同左 | 同左 | 同左 | 同左 | 解锁 |
| **关机** | — | 开机（3s） | — | — | — | — |

设计说明：
- **结束采集必须长按**（防口袋误触/桌面碰触）；短按暂停是低风险操作所以给短按。
- **提醒弹屏上按 REC 直接开录**是点睛之笔：19:00 学生会提醒弹出 → 按一下就开始录会，会话自动命名"学生会"。
- 语音待办 = 对讲机手势：**按住说、松开发**。录制中按住 MARK，服务器取按住期间的音频转写抽取；
  待机时按住 MARK 则临时唤醒麦克风。离线时先本地存（带 RTC 时间戳），联网后补传补建。

```
│   ■ 已结束 41分钟      │      │ REC开录 MARK稍后 BACK知道│

└──────────────────────┘
```

刷新纪律：正文区 15 秒节拍、有新内容才刷；状态栏随正文一起刷；场景切换/确认页用 0.6s 快刷；
每 N 次快刷做一次全刷清残影（N 按实屏调试，先取 20）。

**真机像素预算（250×122 实测于像素版模拟器，硬约束）**：扣除顶栏(14px)/底栏(13px)后，
转写正文≈ **4 行×13px 中文（约 60~72 个可读汉字/屏）**；翻译大字≈ **3 行×17px（约 33 字）**；
待机页时钟 31px + 议程最多 2 行。所有页面设计不得超出此预算；固件字库按 13/17/31px 三档位图准备。

## 5. LED 语义

| LED | 含义 |
|---|---|
| REC(红) | 常亮=录制中；慢闪=暂停；快闪=收尾上传中；双闪一次=已标记重点 |
| FULL(黄) | 常亮=SD 将满(<10%)；慢闪=上传积压大(断网攒了很多)；灭=正常 |
| CHG(绿) | 常亮=充电中；灭=满/未充；开机自检时三灯轮闪一遍 |

## 6. 离线行为（双通道哲学在设备上的延伸）

| 场景 | 断网时 | 恢复后 |
|---|---|---|
| 会议/课堂 | 照常录（SD），屏显"离线录音中"，无实时转写 | 合批补传→云端补转写→纪要照常出 |
| 翻译 | 照常录，屏显"离线，联网后出译文" | 补传后出完整双语记录（实时性天然丢失，如实告知） |
| 语音待办 | 本地存音频+RTC 时间戳，屏回"已存，联网后入日历" | 补传→抽取→入日历，若时间已过则标"已过期待确认" |
| 提醒 | 完全不依赖网络（RTC 本地闹钟） | — |

## 7. 电源与睡眠概要

- 待机主屏：静态显示（墨水屏 0 功耗），分钟级更新时钟；无操作 X 分钟后停止时钟刷新（屏保持最后画面），任意键唤醒。
- 深睡：RTC 闹钟（提醒）与任意键可唤醒；麦克风 LDO（MIC_CTRL）与屏电源（EPD_POWER_EN）分域断电。
- 低电策略：<15% 屏+LED 提示；<5% 拒绝开始新会话；录制中电量耗尽前**先关上传、保 SD 写完整**再关机。
- 充电中（USB-C）：常显充电页（百分比来自 MAX17048）。

## 9. 开放问题（下个开发者/模型从这里接手）

1. **提醒只有视觉**（无蜂鸣器/马达）——学生线"到点提醒"可能被漏看。决策点：下一版改板加振动马达，还是接受"提醒主要靠手机、卡上为辅"。
2. 长按时长（1.5s/3s/5s）与锁键细节需真机手感调校。
3. 翻译场景的实时性指标：ASR出句→译→下推→刷屏全链延迟目标 ≤4s，需真人课堂实测（ROADMAP §5.1）。
4. 待机时钟分钟刷新的功耗实测：若续航压力大，改为"按键唤醒才显时钟"。
5. 双麦当前降混单声道；双麦降噪/波束留 v2（大概率放服务端）。
6. 会话在卡上的命名规则：默认"场景+日期"，提醒开录用事件名；App 内可改。
7. 多设备/多用户的归属已由 v1 绑定与 `binding_generation` 强制；真板发布前仍需做双账号交叉验收。

# 落叶（Luoye）录音卡固件路线图

> 目标硬件：ESP32-S3 N16R8、GDEY0213B74、双 PDM 麦克风、microSD、BQ25186、MAX17048、PCF8563
> 正式固件目录：`D:\OPENOP\recorder-card-hw-test\firmware\recorder-card`
> 内部产品标识：`Luoye`；工程名：`recorder_card`
> 文档状态：V1 实施基线（2026-07-30）

## 1. 不可改变的实施原则

1. **SD 优先**：音频先可靠落卡，网络失败绝不能中断本地录音。
2. **录音与上传解耦**：录音生命周期和上传生命周期分别维护状态。
3. **真实状态驱动 UI**：未收到真实成功事件前，不显示“已保存、已同步、已入日历”。
4. **账号密码不进设备**：录音卡只接收 WiFi 凭据；账号在手机/电脑客户端登录并认领设备。
5. **会话可恢复**：断网、重启、重复分片、ACK 丢失均不能造成丢失或重复录音。
6. **安全收尾优先**：SD 故障、低电量和关机必须等待本地会话安全闭合。
7. **一个版本只解决一个主问题**：上一版本未验收，不进入下一版本。
8. **无证据不完成**：没有构建产物、SHA-256、串口日志和真板测试记录，不标记版本完成。
9. **生产链路强制 HTTPS**：禁止证书失败后自动降级 HTTP。
10. **普通烧录不操作 eFuse**：Secure Boot、Flash Encryption 等不可逆操作必须走独立量产审批。

## 2. 版本状态机

```text
PLANNED
  → IN_PROGRESS
  → CODE_COMPLETE
  → BUILD_PASS
  → READY_TO_FLASH
  → FLASHED
  → BOARD_PASS
  → ACCEPTED
```

任何阶段失败都回到 `IN_PROGRESS`。只有 `ACCEPTED` 版本可以作为下一版本的开发基线。

版本命名：

- 开发构建：`v0.2.0-dev.1`
- 候选构建：`v0.2.0-rc.1`
- 验收版本：`v0.2.0`
- 正式发布：`v1.0.0`

| `v0.7.0-power-recovery` | 电源、恢复和长期稳定性 | agenda-todo | 低电量安全关机、RTC 唤醒、看门狗、长稳 |
| `v0.8.0-ota-security` | OTA 与安全加固 | power-recovery | 签名升级、失败回滚、量产安全配置 |
| `v0.9.0-rc` | 发布候选与故障注入 | 所有功能版本 | 功能冻结，完整产品验收 |
| `v1.0.0` | 首个正式发布 | RC 通过 | 可复制生产和交付 |

## 4. 各版本详细目标

### v0.1.0-baseline：冻结当前基线

目标：证明当前源码能够被重新构建、烧录和复现，保留一个确定可回退的起点。

- [ ] 在正式固件目录初始化 Git 仓库。
- [ ] 排除 `build/`、临时文件、密钥和本机配置。
- [ ] 保存当前源码快照。
- [ ] 使用固定 ESP-IDF 版本执行一次干净构建。
- [ ] 运行状态机 PC 回归测试。
- [ ] 在开发板烧录并保存完整启动日志。
- [ ] 验证按键、LED、墨水屏、麦克风、SD、I²C 和 WiFi 基础能力。
- [ ] 保存 bootloader、partition table、app、assets 和 flash 参数。
- [ ] 生成所有产物 SHA-256。
- [ ] 标记 `fw-v0.1.0-baseline`。

验收限制：

- 该版本只作为开发回退点。
- 不声明配网、账号绑定、可靠补传、字幕、翻译、待办或 OTA 已完成。

### v0.1.1-engineering：工程化与可追踪性

目标：以后每一次烧录都能回答“烧了什么、由什么源码构建、为什么失败”。

- [ ] CMake 注入 `PROJECT_VER`、Git commit、构建时间和硬件版本。
- [ ] 开机串口打印固件版本、commit、IDF 版本、硬件版本、reset reason。
- [ ] 增加统一错误码和子系统状态快照。
- [ ] 事件投递失败必须计数并报警，不允许静默丢失关键事件。
- [ ] 建立 `release/` 打包脚本和 manifest 格式。
- [ ] 固化开发、RC、Release 三套构建配置。
- [ ] 建立接口契约、会话 manifest 和测试向量文档。
- [ ] 固件 release manifest 记录兼容的 API contract、服务器 release 和最低客户端版本。
- [ ] 保证现有按键、屏幕和录音行为无回归。

真板验收：

- 连续重启 20 次版本信息一致。
- 串口日志可定位每个子系统初始化结果。
- 任意构建产物都能追溯到唯一源码提交。

### v0.2.0-storage-safe：可靠录音与安全收尾

目标：在没有网络的情况下，先把录音卡做好成一台可靠录音机。

- [ ] 使用随机 UUID 或设备 UUID + 持久计数生成会话 ID。
- [ ] 创建 `session.json`、`audio.wav`、`marks.jsonl`、`upload.state`。
- [ ] 增加 `STARTING`、`CLOSING`、`STORAGE_ERROR` 等真实状态。
- [ ] 检查所有 `fwrite`、`fflush`、`fsync`、`fclose` 返回值。
- [ ] 短写、卡满、拔卡和文件系统错误立即停止“假录音”。
- [ ] 收到 `SESSION_CLOSE_DONE` 后才能显示“本地已保存”。
- [ ] 会话未闭合时禁止新开录音和进入深睡。
- [ ] 启动扫描未闭合会话，根据真实文件长度修复 WAV 头。
- [ ] 修复 `marks.jsonl` 尾部不完整记录。
- [ ] 记录音频缓冲溢出和丢帧数量。
- [ ] 低电量进入 `CRITICAL_FLUSH`，主动停麦、排空和落盘。
- [ ] 增加“无 SD、SD 满、写失败、MIC 失败、电量不足”页面。

真板验收：

- 录音任意时刻拔卡不会继续显示正常录音。
- 写满 SD 后已有 WAV 保持可播放。
- 录音过程中复位，重启后 WAV 可修复并保留。
- writer 最坏积压下关机仍等待闭合。
- 连续录制 2 小时无丢帧、无文件损坏。

### v0.3.0-provisioning：SoftAP 配网和账号绑定

- [ ] 服务器提供只读 `/api/build-info`，能返回 release、commit、镜像、API contract 和数据库 migration。
- [ ] 使用不可碰撞的制造期 `device_uuid`；dev.1 暂以完整 eFuse MAC 作为稳定工程 ID。
- [x] BACK 长按 3 秒启动带随机密码的 SoftAP。
- [x] 本地配置页只接收 WiFi，不接收账号密码或服务器地址。
- [x] 候选 WiFi 获得 IP 后才提交 NVS。
- [ ] 连接固定 HTTPS 生产服务器并验证证书。
- [x] 固件已实现一次性 code/nonce 请求与墨水屏配对码状态；待服务器实现。
- [ ] 客户端登录后选择账号并 Claim 设备。
- [x] 固件已实现轮询和 Device Token/脱敏账号 NVS 保存；待服务器联调。
- [x] 墨水屏已实现 WiFi、服务器、配对中、成功和错误状态。
- [ ] 支持解绑、重新配对和恢复出厂设置。
- [ ] 401/403 不影响本地录音，只暂停上传并提示重新绑定。

真板验收：

## 5. 版本依赖 Gate

### G0：源码与构建可追踪

未完成 Git 基线、版本注入和可重复构建前，不开始功能修改。

### G1：线上服务器源码同步

线上部署已比本地 `server/` 源码更新。未拿到线上准确源码、数据库 schema 和设备 API 契约前，不开始 `v0.3.0`。

线上事实必须注明证据等级：`线上探测确认 / 线上端到端确认 / 部署源码确认 / 本地旧源码参考 / 待确认`。仅看到路由存在，不等于接口契约或账号隔离已经通过。

### G2：存储安全

未通过 `v0.2.0` 的拔卡、卡满、断电和安全闭合测试前，不允许把“已保存”作为产品文案。

### G3：账号隔离

未通过账号 A/B 隔离、解绑和 Token 吊销测试前，不允许设备上传真实用户录音。

### G4：不可逆安全操作

Secure Boot、Flash Encryption Release、JTAG/下载口限制等 eFuse 操作必须等 `v0.9.0-rc` 通过并单独审批。

## 6. 每版统一完成定义

一个版本只有同时满足以下条件才可标记 `ACCEPTED`：

- [ ] 版本范围内所有清单完成。
- [ ] 单元测试、状态机测试和版本专项测试全部通过。
- [ ] 固定 ESP-IDF 环境下执行干净构建通过。
- [ ] 无新增编译警告；已有警告有明确记录。
- [ ] 产物大小、SHA-256、commit 和 sdkconfig 已归档。
- [ ] 使用候选版本烧录开发板并保存完整串口日志。
- [ ] 真板冒烟测试和版本专项验收通过。
- [ ] 失败场景不会显示虚假成功状态。
- [ ] 上一个 accepted 版本仍可回滚。
- [ ] `FIRMWARE_PROGRESS_LOG.md` 和发布记录已更新。
- [ ] Git commit/tag 与归档产物一一对应。

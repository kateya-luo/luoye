# 落叶 v0.6.1 实时字幕、翻译与墨水屏设计

适用固件：`0.6.1-cloud-v1`

设备 API：`luoye-device-api/1`

交互基准：250×122 HTML 真机像素模拟器

状态：`DEVICE + SERVER IMPLEMENTED / END-TO-END PENDING`

## 数据流

```text
PDM -> SD WAV
          |
          +-> 64 KiB 周期修头、fflush、fsync
          |
          +-> 仅从 committed boundary 读取
                 -> 完整 160 KiB 活动分片
                 -> HTTPS 幂等上传 + 精确 ACK
                 -> GET state?after_revision=N
                 -> 会话/游标/偏移/文本校验
                 -> RAM 最新结果快照
                 -> 墨水屏约 15 秒节流刷新
```

SD 仍是录音真源。网络线程不得读取 writer 尚未 `fsync` 的数据；活动录音的不足
160 KiB 尾部不能提前发送，否则一次失败重试可能让同一个幂等键对应不同正文。
只有会话闭合后才能上传不足一整片的最终尾片。
create 请求不携带会持续变化的 PCM 长度，保证响应丢失后同一 create 幂等键重试时
请求正文仍完全一致；最终长度只在 end 请求中提交。

## 结果一致性

- 服务端为每个活动会话维护单调 `revision`。
- 每个结果带 `upload.received_samples`，设备换算为连续 PCM 字节确认点。
- 设备只接受严格递增 revision、不倒退的连续偏移和不超过本地 ACK 的偏移。
- 原文和译文必须放在同一 translation 对象、同一 revision 中返回。
- 新会话开始时清空旧 RAM 结果，禁止跨会话串字幕。
- `result_revision` 与 `result_pcm_bytes` 写入 `upload.state`，断网恢复后从正确游标继续。
- final 确认云端已完整接管音频与后处理任务；设备持久化 ACK 后删除本地副本，
  最终结果继续在网页端生成，不再占用设备历史同步队列。
- state 只携带游标后的最新受限结果，整个响应不超过设备 8191-byte JSON 上限。
- 正文不写工程日志；本版本也不把完整云字幕另存到 SD。

## 页面映射

### 待机

- 主页：真实 RTC 时间、日期、场景和“暂无同步日程”。日程同步属于 v0.6，不显示
  虚构课程或会议。
- 充电页：USB-C、实际电量、REC/BACK/MARK 操作提示。
- 设备状态页：WiFi、云 API、账号绑定、固定式 SD、充电和固件版本。
- 配网页、绑定页、关机页、提醒页和错误页沿用现有真实状态机。

### 会议录音（2 页）

1. 字幕页：最新 meeting text 显示窗口；离线时明确显示本地保存和稍后补传。
2. 状态页：时长、SD、积压、网络、重点和待办计数。

### 翻译录音（3 页）

1. 译文页：一行原文 + 大字译文。
2. 双语页：同一 revision 的原文与译文上下对照。
3. 状态页：时长、SD、积压、网络、收藏和待办计数。

BACK 循环翻页；REC 暂停/继续，长按结束；MARK 在会议页标重点、翻译页收藏；
长按 BACK 锁键。重要状态立即刷屏，纯正文更新约 15 秒一次，控制墨水屏闪烁和寿命。

## 真实性边界

- 未绑定或云 API 不可用时，不显示字幕/译文，只显示本地录音事实。
- 服务器只返回 `202/204/304` 时，保留上一 revision，不虚构新内容。
- 收尾页只有在本地 WAV 安全闭合后才显示“本地已保存”；只有云可用时才显示
  “纪要生成中/双语生成中”。
- 今日议程、语音待办入日历、最终纪要和完整历史查看依赖后续服务器/客户端，
  不属于本版本设备端完成项。

## 真板验收

1. 会议模式说话 2 分钟，屏幕只显示来自服务器的 revision，正文刷新间隔约 15 秒。
2. 翻译模式核对每屏原文和译文 revision 相同，BACK 三页循环正确。
3. 断网继续录音，显示本地状态；恢复网络后补分片并继续增加 revision。
4. 注入旧 revision、偏移回退、跨会话 ID 和超长/非法 UTF-8，设备全部拒绝。
5. 连续刷新 4 小时，无错位、镜像、严重残影、栈溢出或持续内存下降。
6. 串口日志只出现长度、revision、偏移和状态，不出现会议正文。

上述接口已经实现，但必须完成真板长录音、断网恢复、旧 revision 注入和双账号隔离
测试后，才能标记 `BOARD_PASS` 或 `ACCEPTED`。

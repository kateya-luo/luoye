# 落叶 1.54 寸方屏固件

## 目标

- 面板：Good Display `GDEY0154D67`
- 控制器：`SSD1681`
- 分辨率：`200 × 200`，黑白 1-bit
- 原有 ESP32-S3、双麦、SD、I²C、电源、配网、绑定、上传、议程与待办逻辑继续复用
- 页面视觉唯一来源：`D:\OPENOP\AI录音卡\UI设计图`

## 显示实现

`tools/gen_ui154_assets.py` 按 `docs/luoye_ui_layout_23pages_with_icons.json` 生成
23 个行优先、MSB 在左、`1=黑` 的 5000 字节页面资源。较低阈值不会把
设计图的灰色抗锯齿边缘误判为黑色，因此小字笔画更细、更清楚。生成结果位于
`assets/ui154/`，并随 `assets.bin` 一起烧录。

页面装饰、叶片、曲线、构图和静态文案直接使用设计图取模结果；以下字段在运行时覆盖：

- 时钟、日期和电量
- 今日日程和下一项日程
- Wi-Fi、云端、上传积压和存储状态
- 录音时长、暂停、锁键和安全收尾
- 录音开始时立即显示首帧；实时字幕/章节纪要在自然分钟边界刷新
- 第 23 页“本段纪要”的时间范围、章节标题和两条动态要点
- SoftAP 名称、密码、配对码和绑定账号
- 语音待办文本、时间和日程提醒

SSD1681 首帧用 `0xF7` 建立黑白基准；后续页面使用随屏幕模组提供的 GDEY0154D67
原厂快速初始化序列（`0xB1 → 0x1A/0x64 → 0x91`）和 `0xC7` 快刷。RAM 地址方向沿用
本项目已经验证的方向，因此移植快刷波形不会改变页面朝向。

## 按键定义

| 状态 | REC | BACK | 中间键 |
|---|---|---|---|
| 待机 | 短按开始会议；按住说语音待办，松开保存 | 短按主页/日程/状态翻页；长按 3 秒配网 | 长按进入同步确认页 |
| 同步确认 | 无动作 | 短按取消并回主页 | 短按开始按时间顺序上传历史录音 |
| 同步进行 | 无动作 | 短按回主页，后台继续上传 | 无动作 |
| 录音 | 短按暂停/继续；长按 1.5 秒安全结束 | 短按字幕/状态翻页；长按 3 秒锁键或解锁 | 无动作 |
| 提醒 | 短按开始会议 | 短按关闭；长按 3 秒推迟 10 分钟 | 无动作 |
| 待办确认 | 短按确认 | 短按取消 | 无动作 |

硬件电源开关负责整机断电，因此待机长按 REC 不再承担软件关机。

## 构建与烧录

当前验证构建目录为 `build-v094`，服务器地址为
`http://clearmeeting.chat:34567`。在 ESP-IDF 5.5 CMD 中执行：

```bat
cd /d D:\OPENOP\recorder-card-hw-test\firmware\recorder-card-v070-100ma
powershell -ExecutionPolicy Bypass -File tools\build_profile.ps1 -Profile engineering -ServerBaseUrl http://clearmeeting.chat:34567 -AllowInsecureHttp
idf.py -B build-v094 -p COM22 flash monitor
```

也可使用最终 FLASH 包里的 `flash_COM22.bat`。

## 真板首轮验收

1. 开机首帧允许做一次完整基准刷新，之后页面应为快速刷新。
2. 确认待机页方向、镜像和文字朝向正确。
3. BACK 连按两次，核对日程页、设备状态页。
4. 短按 REC，核对准备页、字幕页和红色录音灯。
5. 再短按 REC，核对暂停页；短按继续，长按结束，核对保存页。
6. 待机按住 REC 说一句待办，松开后核对识别与确认页。
7. 待机长按中间键进入同步确认页；短按 BACK 应取消，重新进入后短按中间键应开始上传。

如果方向不对，只调整 `components/epd_ssd1681/include/epd_ssd1681.h` 中的
`EPD_SWAP_XY / EPD_FLIP_X / EPD_FLIP_Y`，不修改 UI 坐标和页面资源。

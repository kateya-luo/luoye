# V1.7.0 R2：SDSPI 精确长度 DMA 与故障隔离

本版以 V1.5.2 的稳定存储、录音和上传行为为功能基线，只保留
V1.6.0 R2 的纯 RAM 手动续传重启逻辑。V1.6.0 R1 的 NVS 持久化方案
不在本版中；V1.7.0 R1 改变 SD 线上字节数的方案也已撤回。

## 已确认的根因

V1.7.0 R1 为规避 ESP-IDF 5.5.4 的临时 DMA 缓冲分配，把 SDSPI
事务的实际线上长度向上补齐到4字节。最终块原本应为512字节数据加
2字节 CRC，共514字节，却被发送成516字节。

部分 SD 卡会把这两个额外时钟带入下一块边界。现场测速块应以
`0x5A` 开始，实际却以相邻块 CRC 的首字节 `0x5C` 开始；错误块计算
出的 CRC 又与日志完全相同。因此这是确定的协议边界错误，不是
FAT32、卡容量或旧文件造成的，格式化无法修复驱动根因。

复核还发现第二个确定性边界错误：中间块为下一块预读的首字节仍
指向同一个516字节缓冲，旧代码会先清空该缓冲、再复制预读字节，
等同于主动把下一块首字节改成 `0xFF`。R2 在任何缓冲复用前先把
预读内容复制到最终目标，并拒绝超出当前块长度的异常 look-ahead。

## R2 根因修复

- 工程内固定 ESP-IDF 5.5.4 的 `esp_driver_spi` 与
  `esp_driver_sdspi`，构建时核验两个覆盖组件都实际生效。
- 回移 Espressif 后续 `release/v5.5` 的 DMA 判断：ESP32-S3 的内部
  DMA 缓冲只要求地址对齐，不要求有效事务长度也是4字节倍数。
- SDSPI 在设备初始化时一次性预留516字节、4字节对齐、
  `MALLOC_CAP_INTERNAL | MALLOC_CAP_DMA` 的缓冲。
- 上传任务使用 PSRAM 栈，因此命令对象也改为全局串行保护的内部
  DMA 对象；token、busy、CRC、停止命令等全部小事务复用永久缓冲。
- 全部12处 SPI 事务使用 `SPI_TRANS_DMA_BUFFER_ALIGN_MANUAL`，地址或
  能力不满足时直接失败；SDSPI 路径不再在上传压力下临时申请任何
  TX/RX bounce buffer。
- DMA 描述符可以拥有516字节容量，但 HAL 严格按照
  `spi_transaction_t.length` 产生线上时钟：中间块最多516字节，最终
  完整块严格514字节。
- 保留 SPI 私有缓冲 OOM 清理保护，避免任何其他调用者分配失败时
  在清理路径崩溃。

## 运行期故障边界

- SD 初始化完成后进入 `READY`；确认 EIO、ENODEV、ENXIO 或 ETIMEDOUT
  后只允许转入一次 `FAULTED`。
- `FAULTED` 后不热重挂载、不继续扫描、不删除测速文件，也不继续
  `unlink`、`rename`、`fsync` 或可写文件关闭；由下一次重启完整初始化。
- uploader 在 backlog 扫描前检查 `FAULTED`，保留最后已知进度，不再
  每3秒访问卡或刷错误日志。
- 会话目录扫描区分 FOUND、END、ERROR。真实 I/O 错误不能被解释为
  队列为空；单个缺文件、坏 JSON 或孤儿目录会保留并跳过，健康会议
  仍可上传。若只剩逻辑坏目录，手动同步报告失败而不是虚假完成。

## 明确保持不变

- 10 MiB 离线范围及服务器 `upload-plan` 权威断点。
- 单上传任务、16 KiB 应用层内部 DMA 顺序读取。
- SD SPI 固定20 MHz。
- TCP发送65535、接收32768、HTTP TX 16384、TCP SACK。
- 上传期间 `WIFI_PS_NONE`，结束后恢复省电模式。
- 电量显示、充电策略、墨水屏刷新、字幕和待办逻辑。
- 不自动格式化。空 FAT32 卡仍会自动创建 `/rec`、`/diag` 和卡清单；
  exFAT、NTFS 或损坏文件系统只安全拒绝，由用户明确格式化。

## 放行标准

自动检查覆盖 `extra_data_size=0..7` 的精确线上长度与516字节描述符
容量边界，并核验本地 SPI/SDSPI 覆盖组件。真机仍需完成：128 KiB
测速逐字节比对、连续多次超过10 MiB上传、设置键中断后按服务器
缺口续传，以及故障后仅一次 `STORAGE_FAULT` 且无后续 SD 写入。
